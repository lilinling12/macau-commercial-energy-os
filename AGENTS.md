## Authority First

Before any change:

1. Read `docs/00-authority/handoff/CURRENT.md`.
2. Read related authority documents.
3. Check related ADRs.
4. Define validation evidence.

## Engineering Rules

- Do not silently change architecture.
- Do not bypass domain boundaries.
- Do not break contracts without versioning.
- AI generated code follows the same review and validation rules as human code.

## Workflow

Research -> Decision -> Architecture -> Engineering -> Implementation

## UI/UX Workflow

For interface, prototype, accessibility, responsive, chart, or visual-system work, read `.agents/skills/macau-energy-os-ui-ux/SKILL.md` and its linked references. Use the available `ui-ux-pro-max` skill for searchable design guidance, while project authority and evidenced energy semantics control product claims. Record the actual viewport, locale, states, and interaction checks performed; do not describe unrendered or untested work as validated. Keep visual directions and palette studies explicitly provisional until the owner decides.
