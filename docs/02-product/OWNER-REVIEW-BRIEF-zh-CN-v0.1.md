# 产品、架构与交付：Owner 中文评审摘要 v0.1

**状态：** 供产品 Owner 评审；本文件不记录任何已批准的产品、界面或技术决定。  
**日期：** 2026-10-04  
**对应英文决策来源：** [Owner Decision Summary v0.1](OWNER-DECISION-SUMMARY-v0.1.md)

## 目标与决策边界

当前 Goal 已启动，最终目标是完成澳门商业能源产品的用户/问题验证、Owner 批准的产品设计、证据支撑的技术架构和详细设计、经过验证的 MVP、经授权的澳门试点及运营交接。

这只确认了目标和交付标准，**没有批准**目前的产品假设、界面方向、技术栈或部署。文档、原型和绿色 CI 检查都不等于产品验证或交付完成。完整退出标准见[目标章程](../00-authority/PRODUCT-ARCHITECTURE-DELIVERY-GOAL-v0.1.md)和[实施就绪审计](../00-authority/PRODUCT-ARCHITECTURE-IMPLEMENTATION-READINESS-AUDIT-v0.1.md)。

## 当前产品假设

初始产品假设是：把商业站点的能耗数据、物理/结算关系、合同和电价规则连接起来，给出可追溯的成本/需求分析、SHADOW 建议及可回放证据。角色、核心工作流、首发范围和商业价值仍待澳门客户/站点证据验证。

MVP 暂定保持 **SHADOW/建议模式**：不直接控制设备；未核实的 Pu 需求窗口、电费规则、站点关系或数据质量不得被呈现成确定账单或节省。异地光伏不应被推定为另一用电账户的账单抵扣。

| **8** | SHADOW 建议的金额语义 | 建议只有在引用合格、不可变成本评估并注明范围、周期、基线/比较依据和不确定性时才显示金额。可选：显示预计绝对成本；显示相对明确基线的模拟变化；或暂不在建议卡显示货币金额。任何模拟效果都不是实际节省。 | 决定 Recommendation/CostResult 合约与 UI 文案；冻结语义前评审，金额资格仍受 G1/G2/G4/G5 证据约束。 |

| **10** | 首个可控资产（D-003） | HVAC/冷水机可保留为发现阶段假设；也可在现场比较它与 ESS/其他负载；或选定站点后重新评估。现有公开证据不能证明任何指定站点的可控能力、容量、舒适/服务约束或节省。 | 影响 PRD、VS-007 和试点范围；站点测量和 Owner/站点批准前不得称为已确认可控资产。 |
| **11** | 澳门数据治理与跨境处理 | 在任何客户数据接入、外部 AI 处理或试点前，按真实字段/流程审查个人资料适用性、控制者/处理者、用途、存储/支持/子处理方、保留删除及跨境流向，并由负责的隐私/法律人员审查适用条文。不得假定所有楼宇遥测都是个人资料，也不得假定它们都不是。 | 决定数据流、托管、支持、备份与 AI 边界；属具体流向的法律/隐私审查，不是本摘要给出的法律结论。 |

## 决策依赖顺序

15 项不必一次全部批准。按最早的安全决策时点处理；证据前置条件未满足的事项继续标为待定。

| 决策时点 | 对应事项 | 前置证据 / 行动 |
|---|---|---|
| **现在：产品方向评审与研究准备** | #1 产品承诺、#2 首要用户/站点假设、#3 待验证的工作流方向、#4 光伏探索边界、#7 安全基线提案、#8 金额语义方向、#14 授权问题 | 可确定研究重点或明确暂缓。用户角色、视觉系统、账单级经济结果、具体光伏范围和最终权限仍须等待发现研究/Gate 证据；WP-4 验证用户、流程及真实访问需求。 |
| **G6.9-R2 Step 3D runner 冻结前** | #5 UI 对比范围、#6 Temporal 测试持久化、#13 执行主机/信任边界 | 只确定实验环境和比较协议；运行前固定服务拓扑与隔离主机，不借此选择生产框架、数据库或托管方式。 |
| **接入客户数据或外部 AI 处理前** | #11 数据治理/跨境审查、#14 组织与站点授权策略 | 按实际字段和数据流分类，取得站点/客户授权，限定最小数据范围与支持访问，并完成隐私/法律/安全审查；此门槛前不接入真实客户数据。 |
| **连接器/来源盘点后，遥测合约冻结前** | #9 事件身份/重复处理、#12 持久化收据语义 | 依据真实仪表与 BMS 连接器行为确定来源身份及确认映射；保留失败关闭、可恢复和可审计边界。 |
| **领域语义与候选边界明确后，合约 V2/代码生成前** | #15 合约权威来源/工具链 | 使用保留的 TypeScript/Go 证据切片进行比较；跨运行时结果出来后再选择编写、版本化和生成策略，并记录 ADR。 |
| **冻结经济结果标签/合约前** | #8 建议金额语义；相关的 #4 光伏结算范围 | 结合已批准工作流及 G1/G2/G4/G5 证据确定成本结果含义。光伏生产/出口与消费/进口语义依赖站点权利、合同和电表证据；不推定跨站电费抵扣。 |
| **选定试点站点并取得站点证据后，提出可控性或试点声明前** | #4 具体光伏纳入、#10 D-003 资产优先级、#14 站点授权 | 取得站点拓扑、权利、G2 灵活性、运行约束、客户许可和测量方案；批准仅限命名站点与动作，不产生通用资产或控制授权。 |
| **宣称安全控制已验证前** | #7 安全验证基线 | 指定审查人和范围；后续按获批架构执行实现验证。候选 ASVS 对照表本身不代表符合性，也不关闭 G6。 |

若暂缓决定，须保留为明确的开放依赖。沉默不视为批准，任何时点都不能绕过 Gate 或 Owner 审批边界。

## 运行时版本说明

v0.3.0 bake-off 包中的 Node 22.16.0 只对应历史 Step 3C 语义运行记录。当前拟议的 Step 3D runner 对 TypeScript 候选及 Temporal worker 固定为 Node 24.21.0；截至 2026-10-04 的官方版本核查，24.21.0 是 24.x LTS 最新补丁，22.x 最新补丁为 22.23.3。为保证 Step 3D 候选可比，暂按 bake-off pin 准备，并在 runner 冻结时重新核对。这只是测试运行时，不是生产运行时批准。Next.js 不在当前 G6.9-R2 候选集合中，也没有作为后端框架经过本轮比较；若要评估该用途，须先更新比较依据，再用同等证据测试，不能从现有材料推定已选用。

## 技术状态速览

以下均为当前研究中的候选或评估基线，**并非最终架构选择**：

- 前端：React + TypeScript 为候选方案；Next.js 未获选。
- 云端核心：TypeScript/Go 职责组合仍由 G6.9-R2 比较；C+ 尚非胜出方案。
- 工作流：Temporal 候选。
- 数据：PostgreSQL + Timescale 是评估基线。
- 事件：NATS JetStream 候选。
- AI/优化：Python 职责建议，工作负载与部署仍待验证。
- 站点 Edge：Go 职责建议，硬件、协议、密钥和部署仍待验证。
- 插件隔离：Wasm/WASI 为未来方向，当前 MVP 无已验证需求。
- 现有 Node/NestJS 代码仅是 Candidate B 实现证据；Java/Spring 实现路径目前暂停，均不等于技术决策。

## 全目标路线

1. 继续澳门用户、问题和站点证据研究，按 G0–G7 与 G6.9-R2 记录结论和未知项。
2. 经 Owner 审阅和 WP-4 用户验证后批准产品承诺、用户/工作流、MVP 边界和交互设计。
3. 完成 G6.9-R2 Step 3D/4 的可比较实验，再以 ADR/决策记录批准生产架构。
4. 为已批准 MVP 流程补齐 API/事件/数据、授权、安全、故障恢复、可观测性、部署、备份/回滚和运维详细设计。
5. 按获批架构和纵向切片实现 MVP，并提供正向、负向、隔离、安全、故障恢复和验收证据。
6. 在站点授权、数据治理、安全及基线/测量方案齐备后开展澳门试点；记录实测结果、混杂因素和扩大/整改/停止决定，并完成运营交接。

每项决策可按编号回复“同意建议 / 选 A、B、C / 暂不决定，需要补充证据 / 我的方案是……”。未回复不视为批准。完整依据与当前状态见[英文决策摘要](OWNER-DECISION-SUMMARY-v0.1.md)、[完整交付目标章程](../00-authority/PRODUCT-ARCHITECTURE-DELIVERY-GOAL-v0.1.md)和[路线图](../00-authority/ROADMAP.md)。
